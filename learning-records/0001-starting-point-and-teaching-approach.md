# 起点：软件侧有实战经验、硬件侧零基础，目标是把硬件语言算明白

用户自述「完全不了解硬件，只是在做 AI 应用」，但追问后确认软件侧不弱：做过 RAG / Agent / 微调的工程，且用 Ollama / LM Studio / vLLM 跑过本地模型。这意味着他缺的**不是编程能力或模型直觉，而是硬件层的因果链**（为什么慢、为什么放不下、为什么加卡不一定变快）。

选择的第一个教学入口因此不是「GPU 是什么」，而是「用你已经会的一个除法，推出你被卡住的那个数」：decode 的 tok/s 上限 = 显存带宽 ÷ 权重字节数。这条公式同时能解释量化、batch、TP 与选卡，后续课程都挂在这条骨架上。

**Implications**：
- 永远从软件概念（token、上下文、并发、batch）切入，不从电路或指令集切入；但要求每一步都能算出数，不接受「就是这么设计的」。
- 用户明确要求交付物是 Markdown / Excel / Word，不要 PPT → 课程文件用 `.md`，算例用 `.xlsx`。
- 用户学习动因是「面试 / 评审 / 会议里听得懂并判断真伪」，所以练习应偏向**判断题库**（「这个说法合理吗」）而不是工具操作。
- 尚未确认用户本机 GPU 型号，后续「本机验证」类练习需要先问。
